ChatInput Foundation

Brief

把 ChatInput 从 plain textarea 重构为基于 Lexical 的富文本输入,作为 @coss/ui 的一个组件(复用现有 primitive)。本切片:统一 TagNode(渲染与触发解耦)+ Enter 提交 + 结构化序列化;并把 apps/ui 展示站从 Origin-UI particle 画廊换成展示 ChatInput。后续 TriggerComposer 引擎/合并/数据源归 Plan 2–5。

01

架构:两层 Provider 解耦

ChatInput 住在 @coss/ui 里,建在它的基础 primitive 之上。关键解耦:触发能力(后续 TriggerComposer)与渲染能力(TagProvider 注册表)分离——只读展示历史消息只需后者,持久 TagNode 永不依赖触发插件在场。

编辑场景:TagProvider 包住 Composer;TagView 经 useTagRenderer 读注册表(虚线),缺失则降级纯文本
02

数据流:￼ 占位一一对应

序列化遍历 EditorState:文本累加,每个 TagNode 在 text 里产出一个 ￼(U+FFFC),entities[i] 对应第 i 个占位符,顺序严格对应——两个同名 @Alice 也能区分。

下游按 ￼ 切分就位;需纯展示时把 ￼ 换回 @name(来自对应 entity)

05

关键接口

TagNode 的 5 个 flag 是整份计划的去风险核心——让内核原生处理光标跨过与整删,无需手写命令。

src/components/chat-input/tag/TagNode.tsx 
class TagNode extends DecoratorNode<JSX.Element> {
  // 这 5 个 flag → Lexical 内核自动处理「整体跨过 + Backspace 整删」(零命令)
  isInline() { return true }
  isKeyboardSelectable() { return false }   // 光标不进入内部
  isSegmented() { return true }              // 原子单位
  canInsertTextBefore() { return false }
  canInsertTextAfter() { return true }
  decorate() { return <TagView tag={this.__tag} /> }  // 渲染经注册表解耦
}
src/components/chat-input/serializer/types.ts 
interface SubmitPayload {
  text: string            // 每个 tag = 一个 ￼ 占位
  entities: TagEntity[]   // entities[i] ↔ text 第 i 个 ￼
  images: ImagePayload[]
  files: FilePayload[]
  isEmpty: boolean
}
